# BottleForApps

Лёгкое Windows/macOS-приложение для одновременного использования нескольких связок VPN + RDP без виртуальных машин. Нативное окно (Photino), установка через DMG/pkg/zip-установщик, изменение маршрутов — привилегированной службой, поэтому права администратора нужны один раз при установке.

Приложение решает две задачи:

1. До запуска VPN добавляет временные `/32` (IPv4) и `/128` (IPv6) маршруты к публичным VPN endpoint через физический шлюз. Поэтому следующий VPN не пытается подключиться через уже поднятый туннель.
2. Запускает локальный TCP-релей для RDP и привязывает исходящий сокет к выбранному VPN-интерфейсу через `IP_UNICAST_IF` на Windows или `IP_BOUND_IF` на macOS.

Дополнительная нагрузка создаётся только небольшим .NET-процессом и копированием RDP TCP-потока. VM, контейнеров и собственного сетевого драйвера нет.

## Ограничения MVP

- Windows 10/11 или macOS 12+. VPN endpoint поддерживают IPv4 и IPv6; RDP-релей пока работает по IPv4/TCP.
- Изменение маршрутов выполняет служба BottleForApps, устанавливаемая инсталлятором: запрос прав администратора нужен один раз при установке. Без службы приложение работает по прежней схеме (терминал администратора на Windows, системный запрос на macOS).
- VPN-клиент должен создать или активировать отдельный сетевой интерфейс.
- В конфигурации нужно указать все публичные endpoint VPN. Если клиент выбирает адрес из большого динамического пула, укажите DNS-имя и дополнительные имена через повторяющийся `--vpn-endpoint`.
- DNS-адреса endpoint перепроверяются каждые 30 секунд. Новые адреса автоматически получают отдельный маршрут; старые сохраняются до завершения сессии, чтобы не оборвать уже установленное соединение.
- Если DNS вернул IPv6, но у физического интерфейса нет IPv6-шлюза, Bottle остановит запуск до открытия VPN-клиента. Это исключает незаметное подключение endpoint через главный VPN.
- VPN с жёстким kill switch на уровне WFP может блокировать второй VPN независимо от таблицы маршрутов.
- UDP-транспорт RDP через MVP не ретранслируется; `mstsc` переходит на TCP.
- VPN-клиент после закрытия RDP автоматически не отключается: универсального API для сторонних клиентов нет.

## Сборка

Требуется [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

Готовый комплект установщиков на macOS (включает Windows x64 и macOS Apple Silicon):

```bash
chmod +x ./scripts/build-release.sh
./scripts/build-release.sh
```

Итоговый архив: `artifacts/BottleForApps-installers.zip`. Внутри находятся
`BottleForApps-macOS-arm64.dmg`, `BottleForApps-macOS-arm64.pkg`, `BottleForApps-Windows-x64.zip`,
инструкция и SHA-256 суммы.

Windows x64:

```powershell
dotnet build .\BottleForApps.sln
dotnet publish .\src\BottleForApps\BottleForApps.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -o .\artifacts\win-x64
```

Исполняемый файл будет называться `bottle.exe` и не потребует отдельно установленного .NET Runtime.

macOS Apple Silicon:

```bash
chmod +x ./scripts/publish-macos-arm64.sh
./scripts/publish-macos-arm64.sh
```

Исполняемый файл будет находиться в `artifacts/macos-arm64/bottle`.
macOS-сборка self-contained и не требует отдельно установленного .NET Runtime.
Сценарий публикации также добавляет локальную ad-hoc подпись через `codesign`.

## Установка

macOS Apple Silicon — два варианта:

- **DMG** (рекомендуется): откройте `BottleForApps-macOS-arm64.dmg` и перетащите
  BottleForApps в «Программы». Установите pkg, если нужно корпоративное развёртывание
  (он дополнительно ставит службу маршрутов и ссылку `bottle` в PATH).
- **pkg**: выполнит всё то же самое с одним запросом пароля администратора.

Windows x64:

- Распакуйте `BottleForApps-Windows-x64.zip` и запустите **`Install-BottleForApps.bat`** —
  двойной клик, без игры с execution policy. Скрипт скопирует файлы, создаст ярлыки
  с иконкой и один раз спросит UAC для регистрации службы маршрутов.

Оба установщика ставят службу маршрутов, поэтому после установки права администратора
не запрашиваются. Версия приложения задаётся в `src/BottleForApps/BottleForApps.csproj`
(`<Version>`) и автоматически попадает в Info.plist, pkg и DMG.

## Служба маршрутов (bottle-route-helper)

Маршруты к VPN endpoint создаёт привилегированная служба. Инсталлятор регистрирует её
один раз (macOS — LaunchDaemon из `postinstall`, Windows — служба Windows через UAC-запрос),
после чего приложение и панель управления работают без прав администратора.

- macOS: `/Library/PrivilegedHelperTools/local.bottleforapps.route-helper`, unix-сокет
  `/var/run/bottleforapps-routed.sock` (root:admin, 0660) — подключаться могут только члены группы admin.
- Windows: служба `BottleForAppsRouteHelper`, именованный канал `bottleforapps-route`
  (SYSTEM и администраторы — полный доступ, интерактивные пользователи — чтение/запись).
- Служба принимает только операции `add`/`del`/`cleanup` с host-маршрутами `/32`/`/128`:
  адреса валидируются, loopback/multicast/произвольные команды отвергаются. Она не запускает процессы.
- Созданные маршруты учитываются в журнале. Если приложение завершилось аварийно, удалите
  остатки командой `bottle routes cleanup` или перезапуском сессии.
- Запуск без службы: приложение само переходит на прежний способ (`route` через
  `with administrator privileges` на macOS, PowerShell `New-NetRoute` на Windows).

Проверить доступность службы: `bottle doctor` (строка «Служба маршрутов»).

## Первый запуск

### Графический интерфейс

Запустите приложение без аргументов — Bottle откроет нативное окно панели управления:

```bash
./bottle
```

Повторный запуск не создаёт второй экземпляр: приложение показывает уже открытое окно. Закрытие окна с активными подключениями запрашивает подтверждение. Если нативное окно недоступно, панель автоматически откроется в браузере; `bottle gui browser` принудительно использует браузер.

В панели можно создать и изменить профиль, запустить или остановить подключение, посмотреть его состояние и проверить сетевые интерфейсы. После добавления маршрута карточка показывает проверенный путь `endpoint → физический интерфейс → шлюз`. Данные не отправляются во внешнюю сеть: интерфейс доступен только на `127.0.0.1` и работает с теми же локальными профилями, что и команды ниже.

Чтобы явно запустить панель, используйте `bottle gui`. Консольные команды сохранены для автоматизации и диагностики.

### Windows

Посмотреть сетевые интерфейсы:

```powershell
.\bottle.exe interfaces
```

Создать бутылку:

```powershell
.\bottle.exe create office-a `
  --name "Офис A" `
  --vpn "C:\Program Files\Vendor VPN\vpn.exe" `
  --vpn-endpoint vpn.company-a.example `
  --vpn-interface "Vendor VPN Adapter" `
  --rdp 10.20.30.15
```

`--vpn-interface` должен совпадать с именем или описанием из команды `interfaces`. Его можно не указывать: тогда программа выберет интерфейс, который перешёл в состояние `Up` после запуска VPN-клиента.

`--base-interface` задаёт физический Wi-Fi/Ethernet, через который endpoint должен выйти к провайдеру. Если параметр не указан при создании профиля, Bottle определит адаптер один раз и сохранит его конкретное имя в профиле.

Если VPN использует несколько endpoint:

```powershell
.\bottle.exe create office-b `
  --vpn "C:\VPN\client.exe" `
  --vpn-endpoint vpn1.example.com `
  --vpn-endpoint vpn2.example.com `
  --rdp 10.30.0.20
```

Проверить окружение и профили:

```powershell
.\bottle.exe doctor
.\bottle.exe list
.\bottle.exe show office-a
```

После аварийного завершения приложения удалите оставшиеся временные маршруты:

```powershell
.\bottle.exe routes cleanup
```

Запустить PowerShell от имени администратора не требуется (если служба маршрутов установлена):

```powershell
.\bottle.exe start office-a
```

Программа откроет VPN-клиент и будет ждать подключения не более 120 секунд. После появления VPN-интерфейса она запустит `mstsc.exe` через локальный релей. Временные маршруты удаляются после закрытия RDP или по `Ctrl+C`.

Для нескольких бутылок запустите каждую в отдельном окне терминала.

### macOS

Для RDP установите Windows App. Microsoft Remote Desktop больше не распространяется и заменён Windows App.

```bash
./bottle interfaces

./bottle create office-a \
  --name "Офис A" \
  --vpn "/Applications/Vendor VPN.app" \
  --vpn-endpoint vpn.company-a.example \
  --vpn-interface utun7 \
  --base-interface en0 \
  --rdp 10.20.30.15

./bottle start office-a
```

Запускать всё приложение с повышенными правами не требуется. Если служба маршрутов не установлена, macOS отдельно покажет системный запрос для добавления и удаления точечных маршрутов. После подключения VPN будет создан временный `.rdp`-файл, который откроется в Windows App.

Если имя `utun` заранее неизвестно, не указывайте `--vpn-interface`: приложение выберет новый или изменившийся интерфейс после запуска VPN. Явное имя надёжнее; получить его можно сравнением вывода `./bottle interfaces` до и после подключения.

## Параметры

```text
--vpn <path>              путь к VPN-клиенту
--vpn-args <text>         аргументы запуска клиента
--vpn-endpoint <host>     публичный адрес VPN, параметр повторяемый
--vpn-interface <name>    интерфейс VPN
--base-interface <name>   физический интернет-интерфейс
--rdp <host>              внутренний адрес RDP
--rdp-port <port>         по умолчанию 3389
--relay-port <port>       0 означает автоматический выбор
```

Профили находятся в `%LOCALAPPDATA%\BottleForApps\bottles`. Для переноса каталога установите переменную среды `BOTTLE_HOME`.

## Диагностические журналы

Bottle записывает отдельный JSONL-журнал каждого запуска: операции CLI и локального GUI/API,
профили, DNS, сетевые интерфейсы, маршруты, внешние процессы, VPN/RDP и TCP-релей.
Полные исключения сохраняются со стеком вызовов. Журналы старше 30 дней удаляются автоматически.

- Windows: `%LOCALAPPDATA%\BottleForApps\logs`
- macOS: `~/Library/Application Support/BottleForApps/logs`
- другой каталог можно задать переменной `BOTTLE_LOG_DIR`

Создать ZIP для отправки разработчику можно кнопкой **«Собрать логи»** в разделе помощи
или командой:

```text
bottle logs export
```

Чтобы сохранить архив в указанное место: `bottle logs export путь.zip`. Пароли не записываются,
а содержимое аргументов запуска VPN маскируется. При этом архив содержит диагностически важные
пути, имена интерфейсов, IP-адреса и VPN endpoint — при необходимости просмотрите его перед отправкой.

## Как проверить изоляцию

1. Создайте две бутылки с разными VPN.
2. Запустите первую и подключите её VPN.
3. Не закрывая первый RDP, запустите вторую бутылку в другом административном терминале.
4. Посмотрите проверенный путь на карточке. При необходимости выполните `Get-NetRoute` и убедитесь, что IPv4 endpoint имеют `/32`, а IPv6 endpoint — `/128` через физический интерфейс.
5. Проверьте в журналах VPN, что второй туннель подключился к публичному endpoint напрямую.

Если второй клиент всё равно не подключается, временно отключите его kill switch или опцию вида `Block connections without VPN`. Если это запрещено корпоративной политикой, данный клиент нельзя совместить с другим без отдельного сетевого стека.

## Безопасность маршрутов

Создаются только маршруты в `ActiveStore`, поэтому они не являются постоянными. При аварийном завершении процесса они могут оставаться до перезагрузки или отключения интерфейса. Просмотреть их можно так:

```powershell
Get-NetRoute | Sort-Object AddressFamily, DestinationPrefix
```

Удалять маршрут вручную следует только после проверки его destination, interface index и next hop:

```powershell
Remove-NetRoute -DestinationPrefix "203.0.113.10/32" -InterfaceIndex 12
```
