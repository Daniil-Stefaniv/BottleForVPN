# BottleForApps

**Несколько VPN одновременно на одном компьютере — так, чтобы они друг о друге не знали.**

Каждый VPN живёт в собственной «бутылке» — изолированном Linux network namespace внутри WSL2: свой сетевой стек, своя таблица маршрутов, свой DNS. Наружу бутылка отдаёт SOCKS5-прокси и TCP-пробросы на `127.0.0.1` — куда уйдёт трафик, решает бутылка, а не таблица маршрутов Windows. Без драйверов, без перехвата чужого трафика, без прав администратора в повседневной работе.

Управление — из графического приложения или CLI `bottle`: они работают с одним демоном и одним хранилищем профилей и полностью взаимозаменяемы.

![Список бутылок и панель управления](docs/screenshots/gui-list.png)

## Требования

- Windows 10/11 (подходит Home — Hyper-V не нужен) с включённым **WSL2**.
- Права администратора один раз — на включение WSL (и ещё один раз — `bottle-svc --install`, если нужны host-бутылки).
- Конфиг WireGuard (`.conf`) или OpenVPN (`.ovpn`), либо фирменный VPN-клиент (Cisco AnyConnect, FortiClient и т.п.).

## Установка

Готовые сборки — на [странице релизов](../../releases) (собираются CI по тегам версий). Установщики не подписаны сертификатом: SmartScreen предупредит — «Подробнее → Выполнить в любом случае». Контрольные суммы — в `SHA256SUMS.txt` рядом с файлами.

- **MSI (рекомендуется)** — `BottleForApps-<версия>-win-x64.msi`: один UAC ставит CLI, демона, GUI, службу маршрутов, PATH и включает компоненты WSL. Если система просила перезагрузку после включения WSL — перезагрузитесь.
- **Portable** — `BottleForApps-portable-<версия>-win-x64.zip`: распаковать и запустить `bottle-gui.exe`. WSL должен быть включён заранее (`wsl --install --no-distribution` от администратора); только env-бутылки, пока не выполнен `bottle-svc.exe --install` от администратора.

Обновление — MSI новой версии поверх старой; обновление Linux-апплайенса — `bottle upgrade`. Удаление — «Приложения → BottleForApps», профили в каталоге данных остаются.

## Быстрый старт

1. Запустите **BottleForApps** из меню «Пуск» и нажмите **«Запустить демона»** (или стартуйте `bottled` вручную).
2. Вкладка **«Создать»**: выберите файл `.conf`/`.ovpn`, задайте имя — демон скопирует конфиг в хранилище (`%LOCALAPPDATA%\BottleForApps\bottles\`) и запишет профиль.
3. Нажмите **«Старт»** у бутылки (первый запуск включает WSL-VM — до минуты, дальше секунды).
4. Подключайтесь: RDP — `mstsc /v:127.0.0.1:<порт>`, браузер — SOCKS5 `127.0.0.1:<порт>`; адреса копируются из панели бутылки одним нажатием.

Эквивалент в CLI:

```powershell
bottle create office-a --name "Офис А" --kind env --protocol wireguard `
    --config C:\путь\к\office-a.conf --forward 10.20.30.15:3389 --dns 10.20.30.1
bottle start office-a
bottle status    # покажет SOCKS5-порт и пробросы на 127.0.0.1
```

## Команды CLI

`bottle list / show / start / stop / status` — профили и состояние; `create / delete` — управление профилями (занятый id — только с `--force`; удаление поднятой бутылки отклоняется); `doctor` — диагностика окружения (WSL, апплайенс, служба, порты; код возврата 1 при любой ошибке); `logs export` — ZIP с журналами; `upgrade` — пере-импорт Linux-апплайенса; `routes cleanup` — чистка сиротских маршрутов. Все команды понимают `--json` (на этом построен GUI). Полная справка — `bottle --help` и `bottle <команда> --help`.

OpenVPN-конфиги с голым `auth-user-pass`: логин и пароль не хранятся — GUI спрашивает их в диалоге при каждом «Старте», CLI — скрытым вводом в терминале (в скриптах: `bottle start <id> --username <логин> --password <пароль>`; в `--json`-режиме демон отвечает `NeedCredentials`). Креды живут только в памяти сессии и в tmpfs внутри WSL-апплайенса, на диск хоста не пишутся.

## Host-бутылки

Для VPN, которые работают только через фирменный клиент (AnyConnect, FortiClient…): клиент запускается на хосте как есть, а BottleForApps держит точечные маршруты до его шлюзов (служба `bottle-svc`, ставится один раз: `bottle-svc --install` от администратора) и поднимает те же SOCKS5/пробросы на `127.0.0.1`, привязанные к VPN-адаптеру клиента. Env- и host-бутылки работают одновременно. Ограничения: `stop` не завершает фирменный клиент (нет API — остановите вручную), kill switch вендора может конфликтовать с соседними VPN, один экземпляр клиента на бутылку.

## Диагностика

| Симптом | Что делать |
|---|---|
| «Не удалось подключиться к демону» | запустите `bottled` (в GUI — кнопка «Запустить демона») |
| Первый `start` долгий | импорт WSL-образа, до минуты — нормально |
| `failed (handshake timeout)` | endpoint VPN недоступен — проверьте конфиг и связь |
| `Degraded` в status | апплайенс переживает сон/`wsl --shutdown` — авто-восстановление до ~2 минут, ничего делать не нужно |
| Служба маршрутов не установлена | `bottle-svc.exe --install` из PowerShell от администратора |

Журналы — файлы JSONL с ротацией (демон — `<каталог данных>\logs`, служба — `%PROGRAMDATA%\BottleForApps\logs`); выгрузка одним архивом: `bottle logs export` или «Диагностика → Собрать логи».

## Ограничения

Только Windows (порт на macOS отложен по итогам спайка — [отчёт](spikes/vz-poc/REPORT.md); версия 1 для macOS сохранена в ветке [`v1`](../../tree/v1), тег `v1-mvp`). UDP не ретранслируется — SOCKS5 в режиме TCP (RDP и браузеры работают). Автозапуск демона не ставится установщиком — ярлык в `shell:startup` вручную. Установщики не подписаны.

## Сборка из исходников

Нужны Rust (stable) и Docker (для Linux-образа).

```bash
cargo test --workspace                                        # тесты ядра
cargo build --release -p daemon -p cli -p svc                 # бинарники Windows
bash appliance/build-rootfs.sh                                # Linux-апплайенс → artifacts/

cd gui && npm ci
npm run lint && npm run test && npm run build                 # web-часть GUI
npm run tauri build                                           # release-сборка bottle-gui
```

Посмотреть UI без Windows и демона: `npm run dev` в `gui/` и открыть `http://localhost:5173/?demo=1` (демо-данные; `?demo=down` — панель «демон не запущен»).

Устройство репозитория: `crates/` — ядро (core, agent, daemon, svc, cli, relay-lib), `gui/` — Tauri-приложение, `appliance/` — сборка Linux-образа, `installer/` — WiX-проект MSI, `docs/` — спецификация и чеклисты приёмки.
