# Погребок 0.3 — дизайн-документ

Дата: 2026-10-21
Статус: согласовано в диалоге, ожидает письменного ревью
Преемник: BottleForApps 0.2.x (roadmap M5)

## 1. Контекст

BottleForApps 0.2.x: несколько VPN одновременно, каждый в своей «бутылке»
(изолированный netns в WSL2 или точечные маршруты на хосте). Управление —
Tauri GUI и CLI `bottle`, которые являются равноправными клиентами демона
`bottled`; профили хранятся файлами `%LOCALAPPDATA%\BottleForApps\bottles\*.toml`,
копии VPN-конфигов — `*.conf` рядом; OpenVPN-креды не хранятся нигде и
спрашиваются при каждом старте.

Релиз 0.3 — смена центра тяжести: **GUI становится источником истины**,
хранилище переезжает в зашифрованную БД, продукт получает имя «Погребок»
(Pogrebok) и новый UX.

### Цели (принятые требования)

1. GUI — источник истины: демон, бутылки, конфигурации подчиняются GUI.
2. В GUI — команды запуска/остановки демона и консоль контроля состояний.
3. «Диагностика» = полное логирование: операции демона, команды GUI, служба.
4. Бутылки разделены на страницы env и host.
5. Хранилище — легковесная БД под паролем; логины/пароли бутылок — в ней же.
6. Список бутылок отображается и при остановленном демоне.
7. При запуске приложения — ввод пароля БД, иначе входа нет.
8. «Создать» — модальное окно поверх главного, блокирующее его.
9. У бутылки — кнопка обновления логина и пароля (диалог с «Сохранить»).
10. Новое название и логотип.

### Ограничения

- Никаких внешних технологий, требующих отдельной установки: всё линкуется
  статически или лежит в portable. Из новых зависимостей — только SQLCipher
  (встраивается в бинарник).
- Платформа — Windows 10/11 (WSL2). Стек прежний: Rust (core/agent/daemon/svc)
  + Tauri 2 + vanilla TS/Vite. Electron и внешние СУБД не рассматриваются.
- Миграция с 0.2.x обязана сохранить существующие бутылки пользователей.

### Принятые архитектурные решения (из вопросов-ответов)

| Решение | Выбор |
|---|---|
| Владелец БД | **GUI** (вариант B); демон — исполнитель без хранилища |
| CLI `bottle` | Управление бутылками убрано; остаются служебные команды |
| Закрытие окна | Сворачивание в трей; GUI и демон живы |
| Выход из трея | «Завершить» + подтверждение да/нет → гаснут демон и GUI |
| Консоль демона | Живая панель внутри вкладки «Диагностика» (вариант A) |
| Забытый пароль | Только сброс с полной потерей данных, без компромиссов |
| «Запомнить пароль» | Нет; пароль спрашивается всегда (вариант A) |
| Название | **Погребок / Pogrebok**; термин «бутылки» сохраняется |

## 2. Архитектура

```
┌─────────────────────────────┐         ┌──────────────────────────┐
│  pogrebok-gui (Tauri)       │  pipe   │  pogrebok-daemon         │
│  ─ экран блокировки         │◄───────►│  ─ реестр профилей в RAM │
│  ─ SQLite+SQLCipher (владеет│ Hello/  │  ─ рантайм бутылок       │
│    БД, ключ, креды)         │ Sync/   │  ─ WSL-апплайенс, агент  │
│  ─ журнал gui-*.jsonl       │ push-   │  ─ журнал daemon-*.jsonl │
│  ─ спавн/остановка демона   │ события │  ─ svc_client            │
└─────────────────────────────┘         └──────────────────────────┘
                                                     │
                                          ┌──────────▼───────────┐
                                          │ pogrebok-svc (служба)│
                                          └──────────────────────┘
```

- БД открывает только GUI; мастер-пароль и ключ никогда не покидают его процесс.
- Демон не читает и не пишет дисковое хранилище: профили, тексты конфигов и
  креды получает от GUI по IPC и держит в памяти (модель OpenVPN-кредов 0.2.x,
  распространённая на всё).
- Команды `create/delete` демона исчезают; мутации: GUI → транзакция БД →
  синхронизация в демон.

## 3. UX и экраны

Макеты согласованы в визуальном компаньоне:
`.superpowers/brainstorm/72963-1792598971/content/` (файлы `layout-main-v5.html`,
`diagnostics.html`, `lock-and-modals.html`).

### 3.1 Экран блокировки

- Показывается до главного окна; без разблокировки приложение не пускает дальше.
- Обычный запуск: поле пароля + «Разблокировать»; неверный пароль — сообщение
  под полем, без лимита попыток; «Запомнить пароль» отсутствует.
- «Забыли пароль?» → диалог с честным предупреждением: сброс = удаление БД,
  бутылки создаются заново; требует подтверждения.
- Первый запуск: создание мастер-пароля с подтверждением и индикатором
  надёжности; предупреждение о невозможности восстановления.
- Смена пароля — в настройках главного окна (`PRAGMA rekey`).

### 3.2 Главное окно

- Вкладки сверху: **Env · N**, **Host · N**, **Диагностика**; справа — кнопка
  «+ Создать бутылку». Счётчики N обновляются из БД.
- Список бутылок — строгая сетка, одинаковая во всех строках:
  `бутылка (резиновая) · статус 86px · Стоп/Старт 74px · Изменить 86px · Логин и пароль 110px`.
  - Команды никогда не исчезают — неприменимая гаснет с подсказкой
    («у WireGuard нет логина/пароля»).
  - Длинные имена — многоточие + tooltip.
  - Мета-строка: протокол, socks5-порт, пробросы, причина failed.
- Статусы бутылки: `up` (зелёный), `stopped` (серый), `failed` (янтарный, с
  причиной), `degraded` (янтарный), `демон выкл.` (при остановленном демоне).
- Нижняя командная панель (видна на всех вкладках): статус демона ·
  «Запустить/Остановить демона» · «Консоль» (переход на Диагностику) · метка
  времени обновления.
- При остановленном демоне список читается из БД и полностью виден (п.6);
  активны «Изменить» и «Логин и пароль», «Старт» погашен.
- Удаление бутылки — внутри окна редактирования, с подтверждением; удаление
  поднятой бутылки запрещено.
- Редактирование поднятой бутылки: сохраняется в БД, демон помечает
  «применится после перезапуска».

### 3.3 Модальные окна

- «Создать бутылку» и «Изменить» — отдельное окно ОС поверх затемнённого
  главного; главное заблокировано до закрытия модального (п.8). Переключатель
  env/host меняет набор полей; для OpenVPN — чекбокс «сохранить логин и
  пароль», при включении второй шаг окна спрашивает логин/пароль.
- «Логин и пароль» (п.9) — компактный модальный диалог: логин, пароль,
  «Сохранить» / «Отмена». Значения уходят в БД; демон получает их только при
  старте бутылки (в память).

### 3.4 Вкладка «Диагностика»

1. Карточки состояния: демон (pid, версия), uptime, бутылки активных/всего,
   память/CPU процесса, состояние WSL-VM и версия апплайенса.
2. Живая консоль: единый поток событий всех источников; колонки
   `время · уровень · источник · событие · описание`; фильтры-чипы по
   источнику (демон/gui/служба), уровню и категории события; поиск с дебаунсом;
   пауза без потери событий; автопрокрутка.
3. Подвал консоли: «Собрать логи (ZIP)», «Открыть папку логов».
4. Doctor-проверки окружения внизу вкладки.

### 3.5 Трей и выход

- Крестик главного окна = сворачивание в трей; приложение и демон живы.
- Меню трея: «Открыть Погребок», статус демона, «Завершить».
- «Завершить» → подтверждение «да/нет» (при активных бутылках — с их
  перечислением) → `Shutdown` демону → выход; ключ и креды выгружаются из
  памяти обоих процессов.
- Второй экземпляр GUI не запускается (single-instance): сообщение
  «Погребок уже запущен».

## 4. Хранилище (SQLCipher)

Файл `pogrebok.db` в каталоге данных (`%LOCALAPPDATA%\Pogrebok\`; portable —
рядом с exe). SQLCipher (AES-256, `rusqlite` + `bundled-sqlcipher-vendored-openssl`,
статическая линковка). Ключ из мастер-пароля штатным KDF SQLCipher.

```sql
CREATE TABLE meta (
  key   TEXT PRIMARY KEY,   -- 'schema_version', 'kdf_check', 'created_at'
  value TEXT NOT NULL
);

CREATE TABLE bottles (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  kind        TEXT NOT NULL CHECK (kind IN ('env','host')),
  vpn_json    TEXT NOT NULL,   -- VpnConfig как в core::profile
  expose_json TEXT NOT NULL,   -- ExposeConfig как в core::profile
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);

CREATE TABLE configs (
  bottle_id   TEXT PRIMARY KEY REFERENCES bottles(id) ON DELETE CASCADE,
  config_text TEXT NOT NULL    -- полный текст .conf/.ovpn после инлайнинга
);

CREATE TABLE credentials (
  bottle_id  TEXT PRIMARY KEY REFERENCES bottles(id) ON DELETE CASCADE,
  username   TEXT NOT NULL,
  password   TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- Конфиги VPN переезжают из файлов `*.conf` в `configs.config_text` — на диске
  секретов открытым текстом больше нет.
- `vpn_json`/`expose_json` — JSON-снапшоты существующих serde-структур
  `core::profile`: параллельной модели не плодим, миграция тривиальна.
- `meta.kdf_check` — известное значение, зашифрованное ключом: неверный пароль
  отличается от повреждённой БД мгновенно.
- PRAGMA: `journal_mode = WAL`, `synchronous = NORMAL`.
- Все мутации — в транзакциях (бутылка + конфиг + креды атомарно).
- Миграция 0.2.x: при обнаружении `%LOCALAPPDATA%\BottleForApps\bottles\`
  после разблокировки предлагается импорт одной кнопкой (TOML → INSERT);
  старые файлы не удаляются (бэкап).

## 5. Протокол GUI ↔ демон

Транспорт прежний (named pipe, JSON-фреймы из `core::protocol`). Демон не
имеет команд чтения/записи хранилища.

| Сообщение | Направление | Смысл |
|---|---|---|
| `Hello { gui_token }` | GUI → демон | Авторизация сессии; токен (32 байта) генерируется GUI и передаётся демону при спавне |
| `SyncProfiles { profiles }` | GUI → демон | Полная синхронизация реестра: профили + тексты конфигов + креды; после `Hello` |
| `UpsertProfile { profile }` / `RemoveProfile { id }` | GUI → демон | Инкрементальная синхронизация при одиночных мутациях БД |
| `StartBottle { id }` / `StopBottle { id }` | GUI → демон | Креды демон уже имеет — диалог при старте не нужен |
| `StateChanged { id, state, socks5, forwards }` | демон → GUI | Push-событие вместо поллинга status |
| `LogEvent { ts, level, src, event, desc, ctx }` | демон → GUI | Живой поток для консоли |
| `Shutdown {}` | GUI → демон | Стоп всех бутылок → выход |
| `Doctor {}` / `LogsExport {}` | GUI → демон | Без изменений |

Жизненный цикл: блокировка → главное окно (список из БД) → «Запустить демона»
→ спавн с токеном → `Hello` → `SyncProfiles` → работа. Падение демона →
статусы `unknown`, кнопки стартов гаснут, предлагается перезапуск; реестр
восстанавливается повторным `SyncProfiles`.

CLI `pogrebok.exe`: `doctor`, `logs export`, `svc ...`. Команды управления
бутылками удалены.

## 6. Логирование (событийная модель)

Каждая запись — событие из реестра, а не свободный текст. Формат JSONL,
единый для всех источников:

```json
{"ts":"2026-10-21T21:12:04.331Z","level":"info","src":"gui",
 "event":"bottle.start.requested",
 "desc":"Пользователь запустил бутылку «Офис А» (office-a)",
 "ctx":{"bottle_id":"office-a"}}
```

- `level`: `debug / info / warn / error / fatal` (fatal — смерть компонента).
- `event`: код из реестра, нотация `категория.действие.исход`.
- `desc`: описание по шаблону реестра с подставленными параметрами.
- `ctx`: структурные параметры; **секреты запрещены** (пароли, ключи, тексты
  конфигов в лог не попадают никогда; тест-сканер в CI).

Реестр событий — единый каталог (`core::events` + зеркало в GUI): код,
категория, уровень по умолчанию, шаблон описания. Ядро реестра:

| Код | Уровень | Описание |
|---|---|---|
| `db.unlocked` | info | Хранилище разблокировано |
| `db.unlock_failed` | warn | Неверный мастер-пароль (попытка {n}) |
| `db.rekeyed` | info | Мастер-пароль изменён |
| `db.corrupt` | fatal | Хранилище повреждено: {detail} |
| `daemon.spawned` | info | Демон запущен (pid {pid}) |
| `daemon.exited` | error | Демон завершился неожиданно (код {code}) |
| `daemon.shutdown` | info | Демон остановлен по команде пользователя |
| `profiles.synced` | debug | Демону передано профилей: {count} |
| `bottle.created` / `bottle.updated` / `bottle.deleted` | info | Бутылка {id} создана / изменена / удалена |
| `bottle.credentials_updated` | info | Обновлены логин и пароль бутылки {id} |
| `bottle.start.requested` | info | Пользователь запустил бутылку {id} |
| `bottle.up` / `bottle.failed` | info / error | {id} поднята (socks5 :{port}) / {id}: {reason} |
| `wsl.imported` | info | Апплайенс импортирован |
| `svc.route_added` | debug | Маршрут {cidr} добавлен |

Файлы: `logs/gui-YYYYMMDD.jsonl`, `logs/daemon-*.jsonl` (как сейчас),
служба — свой файл; ротация по дате + лимит ~50 МБ на источник. Демон пушит
каждую запись в GUI как `LogEvent`. Консоль: кольцевой буфер 5000 строк,
виртуальный список, пауза без потерь. Экспорт ZIP включает gui-логи.

## 7. Обработка ошибок

- Неверный пароль ≠ повреждённая БД (`kdf_check`): «попробуйте ещё раз» vs
  диагностика + восстановление/сброс.
- `SQLITE_BUSY` на старте → «Погребок уже запущен», выход без порчи данных.
- Разрыв pipe с демоном → «демон остановлен», `daemon.exited`, бутылки
  `unknown`, предложение перезапуска.
- Мутации БД — транзакции; недоставленный `SyncProfiles`/`UpsertProfile` при
  выключенном демоне — не ошибка (полный sync при следующем старте).
- Ошибки старта бутылки — `failed` с причиной в строке бутылки + событие.
- Все вызовы демона асинхронны, с таймаутом и понятным текстом; длинные
  операции (импорт апплайенса) — с прогрессом, UI не блокируется.

## 8. Тестирование

- Rust unit: CRUD БД, транзакции, миграция TOML→БД на фикстурах 0.2.x,
  kdf_check, реестр событий (сериализация всех кодов, соответствие desc/ctx),
  in-memory реестр демона (атомарный sync, старт без диска).
- Rust integration: `Hello/SyncProfiles/Shutdown` через тестовый pipe;
  «демон без профилей не стартует бутылку»; сканер «секреты не в логе».
- TS (vitest): список из локальной модели без демона, сетка команд
  (disabled-состояния), консоль (фильтры, пауза, буфер), экран блокировки.
- Smoke-чеклист (docs/checklists): первый запуск → пароль → миграция →
  бутылка up; выход через трей; демон выкл. → список виден, креды правятся.
- CI: кэширование сборки vendored OpenSSL.

## 9. Оптимизация

- Push-события вместо поллинга; watchdog-сверка раз в 30 с.
- GUI ↔ демон напрямую по pipe, без спавна `bottle.exe` на действие.
- Виртуальные списки (консоль, бутылки); дебаунс поиска 150 мс; рендер лога
  батчами по rAF.
- Release: `opt-level = "z"`, `panic = "abort"` для GUI, LTO+strip (есть);
  иконки SVG.
- WAL + `synchronous = NORMAL`; SyncProfiles одним SELECT с JOIN;
  инкрементальные `UpsertProfile`/`RemoveProfile` вместо полного sync.
- KDF в фоновом потоке с честным спиннером.
- Горячие клавиши: `Ctrl+,` настройки, `Ctrl+L` диагностика, `F5` обновить,
  `Esc` закрыть модальное.
- Состояние окна (размер, вкладка, колонки) — в БД, восстанавливается.

## 10. Логотип и брендинг

- Имя: **Погребок (Pogrebok)**. Тон: тёплый, но инженерный.
- Концепт логотипа: погребок/полки с бутылками, одна ячейка — «светящийся»
  туннель. Формат: SVG-мастер, производные .ico/.png для Tauri и установщика.
  Отрисовка — отдельной задачей (kimi-design), не блокирует план реализации.

## 11. Вне объёма 0.3

- Порт на macOS (отложен в M4B).
- Автозапуск демона без GUI, работа демона как службы.
- «Запомнить пароль» / Windows Credential Manager.
- Интерактивный терминал команд внутри GUI.
- UDP-ретрансляция в SOCKS5.
