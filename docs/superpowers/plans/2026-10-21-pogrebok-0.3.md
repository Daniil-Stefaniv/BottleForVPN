# Погребок 0.3 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** Перевести BottleForApps 0.2.x на архитектуру «GUI — источник истины»: зашифрованная БД SQLCipher под мастер-паролем, демон-исполнитель без хранилища, новый UX (блокировка, вкладки env/host, консоль, модальные окна), ребрендинг в «Погребок».

**Архитектура:** GUI (Tauri) единолично владеет БД и ключом; демон получает профили/конфиги/креды по pipe и держит их в памяти. Канал GUI↔демон: control-соединение (запрос/ответ, как сейчас) + event-соединение (`Subscribe` → поток `DaemonEvent`). Все логи — события из реестра `core::events` в формате JSONL.

**Стек:** Rust (core/daemon/svc/cli), Tauri 2 + vanilla TS/Vite, rusqlite + `bundled-sqlcipher-vendored-openssl`, tokio.

**Спека:** `docs/superpowers/specs/2026-10-21-pogrebok-0.3-design.md`

## Global Constraints

- Платформа: Windows 10/11; сборка и `cargo test --workspace` обязаны проходить и на macOS (dev-машина), транспорт UDS сохраняется для тестов.
- Никаких внешних установок: SQLCipher/OpenSSL линкуются статически; portable-сборка обязана работать.
- UI-копирайтинг — русский; имя продукта «Погребок», термин «бутылки» сохраняется.
- Секреты (пароли, ключи WireGuard, тексты конфигов) не попадают в логи и на диск открытым текстом.
- Формат события лога: `{"ts","level","src","event","desc","ctx"}`; уровни `debug/info/warn/error/fatal`; `src ∈ {daemon, gui, svc}`.
- Pipe демона до Фазы 6 остаётся `\\.\pipe\bottled`; переименование — отдельной задачей (Task 20), обе стороны меняются одним коммитом.
- Демон без `--gui-token <hex64>` отказывается обслуживать канал (защита от чужого клиента).

## Review Focus

Спека умалчивает о пяти классах входов, которые сломают систему, если их не закрепить тестами:

1. **Мастер-пароль с юникодом, пробелами, эмодзи** — KDF обязан принимать произвольный UTF-8 без нормализации-сюрпризов → тест в Task 8.
2. **Битый TOML-файл при миграции 0.2.x** — один повреждённый профиль не должен ломать импорт остальных → тест в Task 10.
3. **Разрыв event-соединения при живом control** (демон перезапущен, GUI держит подписку) — GUI обязан переподписаться после повторного `Hello` → тест в Task 11.
4. **Огромный инлайн-конфиг OpenVPN (≥1 МБ)** в `configs.config_text` и `SyncProfiles` — кадр u32 вмещает, но БД и реестр не должны деградировать → тест в Task 9.
5. **Дубль id при создании бутылки через модальное окно** — отказ с понятной ошибкой, БД не тронута → тест в Task 9 (БД) и проверка в Task 16 (UI).
