# Ручной smoke-чеклист GUI (M4, Task 5)

CI собирает GUI (джоба `gui-build`: eslint → vitest → fmt/clippy → cargo
test → tauri build), но поведение окна на CI не проверяется — этот
чеклист прогоняется вручную перед релизом (macOS и Windows).

Запуск для проверки: `cd gui && npx tauri dev` с подсунутым CLI
(`BOTTLE_GUI_BOTTLE_BIN=<путь к bottle> BOTTLE_GUI_BOTTLED_BIN=<путь к
bottled>` для macOS-хоста; на Windows CLI находится рядом/в PATH).

## Список и управление (Task 3)

- [ ] Окно открывается, заголовок BottleForApps, таблица бутылок на месте.
- [ ] `bottle --json list` без демона: панель «Демон не запущен» с кнопкой
      «Запустить демона» и журналом bottled после нажатия.
- [ ] Список обновляется сам (поллинг 2 с): состояние/порты меняются без
      перезагрузки окна.
- [ ] Старт бутылки: кнопки строки блокируются на время `starting`.
- [ ] Остановка host-бутылки: тост с предупреждением «VPN-клиент остаётся
      запущенным» (дословно из демона).
- [ ] Ошибка CLI (например, старт несуществующей) — тост с текстом демона.

## Create/edit и doctor (Task 4)

- [ ] Форма create: env-поля видны для env, host-поля для host.
- [ ] «Выбрать файл…» открывает системный диалог, путь попадает в поле.
- [ ] Создание с занятым портом: красная строка под формой с сообщением
      демона дословно (клиентской валидации нет).
- [ ] «Изменить» в строке: форма заполнена из show, id серый (readonly),
      submit отправляет create --force.
- [ ] Doctor-таб: таблица ✓/⚠/✗, «Проверить снова» перечитывает.
- [ ] «Собрать логи»: путь к ZIP показан, «Открыть папку» открывает Finder
      (macOS) / Explorer (Windows) с выделенным файлом.

## Tray и полировка (Task 5)

- [ ] Tray-иконка в меню-баре/трее; меню: «Показать окно», бутылки
      (макс 8, потом «…»), «Выход».
- [ ] Подменю бутылки: Старт/Стоп работают, состояние (●/○) обновляется.
- [ ] Закрытие окна скрывает его в tray, GUI жив; «Показать окно»
      возвращает; «Выход» завершает GUI, **демон остаётся жить**
      (документированное поведение).
- [ ] `--no-tray`: `bottle-gui --no-tray` — иконки нет, закрытие окна
      завершает приложение.

## Двойной запуск (Task 12 проверит глубже)

- [ ] Второй экземпляр GUI не создаёт вторую иконку/второе окно рядом
      (если создаёт — фиксится single-instance в Task 12).
